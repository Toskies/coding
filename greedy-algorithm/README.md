# 贪心算法

贪心算法的核心思想是：每一步都做出当前看起来最优的选择，希望通过一系列局部最优，最终得到全局最优。

和回溯、动态规划不同，贪心算法没有特别固定的模板。它更像一种解题思路：先观察问题的目标，再思考每一步到底应该“贪”什么，然后证明这种局部选择不会破坏整体最优解。

## 贪心算法适合解决什么问题

贪心算法一般适合解决如下几类问题：

- 求最值问题：如最多、最少、最大、最小。
- 每一步都可以做出一个相对独立的选择，并且这个选择会让结果朝着目标更接近。
- 当前选择一旦做出，不需要像回溯那样撤销，也不需要像动态规划那样枚举大量状态。
- 能够找到一种局部最优策略，并证明它可以推出全局最优。

如果一个问题的最优解依赖于后面非常复杂的状态变化，或者当前选择会严重影响未来并且很难证明正确性，那么往往就不是纯贪心，而更可能是动态规划或搜索。

## 如何理解贪心算法

贪心算法最重要的两个关键词是：

- 局部最优
- 全局最优

所谓局部最优，就是在当前这一步先选一个最好的方案。所谓全局最优，就是最终得到整个问题的最优解。

贪心算法真正难的地方，不是“怎么贪”，而是“为什么这样贪是对的”。因为不是所有局部最优都能推出全局最优。

例如有些题里，“先选最小的”“先选最大的”“先结束得最早的”“先覆盖最远的”就是正确策略；但也有很多题目中，直觉上的局部最优会把后面的选择空间变差，最后反而得不到最优解。

所以做贪心题时，要始终记住一句话：

> 贪心不是靠感觉选，而是先提出策略，再想办法证明这个策略不会吃亏。

## 贪心的套路

### 什么时候考虑用贪心

遇到下面这些信号时，可以优先想一想贪心：

- 题目在求最大值、最小值、最多数量、最少次数。
- 题目可以拆成若干步决策，并且每一步都在做选择。
- 题目中的选择有明显的排序依据，比如大小、区间左端点、区间右端点、收益、代价、覆盖范围等。
- 你能直觉上想到“当前这一步怎么选最划算”。

很多贪心题一开始看起来没有思路，本质上是没有找到“这一题到底该按什么顺序处理、每一步该优先保住什么”。

### 怎么找贪心切入点

可以按下面的顺序思考：

1. 题目的最终目标是什么。
2. 为了更接近这个目标，当前这一步最应该优先保证什么。
3. 这个优先级能不能通过排序来体现。
4. 做出当前最优选择后，会不会影响后续得到最优解。

很多时候，排序就是贪心的起点。因为排序可以帮助我们把“优先处理谁”这件事固定下来。

常见的贪心切入角度有：

- 优先满足小的需求。
- 优先选择结束更早的区间。
- 优先覆盖更远的位置。
- 优先选择代价更小或收益更大的方案。
- 优先保留更多后续选择空间。

### 怎么验证贪心策略对不对

贪心最关键的是验证，而不是套模板。常见的验证方式有：

- 手动模拟：拿几个小样例一步一步推，看策略是否稳定。
- 举反例：尝试构造特殊情况，看看策略会不会翻车。
- 交换法：假设最优解不是这样选的，尝试交换顺序后，结果不会更差。
- 归纳理解：前面若干步都按这个策略选不会更差，那么下一步继续这样选也不会更差。

如果一个贪心策略总是很难证明，而且你总能构造出反例，那就要及时换思路，考虑动态规划或搜索。

## 贪心解题通用步骤

贪心没有统一代码模板，但有比较稳定的思考流程：

### 1. 明确题目的全局目标

先问自己：这道题到底是在求什么？

- 最多能完成多少个
- 最少需要多少次操作
- 能否覆盖到终点
- 如何让总收益最大

只有全局目标明确了，才能继续想局部最优。

### 2. 设计局部最优策略

思考当前这一步应该优先选择谁、保住什么、舍弃什么。

这里最常见的想法是：

- 先满足胃口小的
- 先选结束早的
- 先走到当前能覆盖的最远位置
- 先处理最影响整体结果的元素

### 3. 决定是否需要排序

很多贪心题本质上都是“排序 + 一次遍历”。

要想清楚：

- 按什么排序
- 从前往后还是从后往前遍历
- 遍历过程中维护什么状态

### 4. 验证局部最优能否推出全局最优

这是贪心题最关键的一步。如果这一步说不清楚，代码写得再顺也不稳。

### 5. 编码实现并处理边界

重点检查：

- 空数组
- 只有一个元素
- 排序后的相等情况
- 区间边界是否取等
- 遍历结束后答案是否需要补一次更新

## 题型粗分类

贪心题的外表很多，但常见思路可以先粗分成下面几类。

### 1. 分配与匹配类

这类题通常有两组对象，需要尽可能多地匹配成功，或者以最小代价完成匹配。

典型思路：

- 先排序。
- 优先用“刚刚好够用”的资源去满足当前需求。
- 小需求优先满足，大资源尽量留给更大的需求。

典型题目：

- `455. 分发饼干`

这类题的关键是：不要浪费大资源。能用小的满足，就不要急着用大的。

### 2. 区间处理类

这类题和区间 `[start, end]` 有关，常见目标是：

- 选出最多不重叠区间
- 删除最少区间
- 用最少的点、箭或操作覆盖所有区间

典型思路：

- 通常先按左端点或右端点排序。
- 常见贪心是优先处理结束早的区间，因为它对后续影响更小。
- 本质是在尽量给后面的区间留空间。

典型题目：

- `435. 无重叠区间`
- `452. 用最少数量的箭引爆气球`
- `763. 划分字母区间`

### 3. 跳跃与覆盖类

这类题关注的是当前能到哪里、下一步最远能扩展到哪里。

典型思路：

- 遍历过程中维护当前覆盖范围。
- 每次都尽量把下一步能覆盖的范围扩到最远。
- 如果当前下标已经超过可覆盖范围，说明无法到达。

典型题目：

- `55. 跳跃游戏`
- `45. 跳跃游戏 II`

这类题的本质是：站在当前位置，不一定马上跳得最远，但要让“下一层能到的最远边界”尽可能大。

### 4. 利润与资源调度类

这类题通常和收益累计、资源消耗、过程中的盈亏平衡有关。

典型思路：

- 只要当前这一步有正收益，就先拿到。
- 或者在遍历过程中维护剩余资源、累计收益、最小成本。
- 关注的是“当前做这个选择是否一定不亏”。

典型题目：

- `122. 买卖股票的最佳时机 II`
- `134. 加油站`

这类题很多时候不需要真正模拟所有方案，而是抓住“有利润就收集”“局部亏损会不会导致整体失败”这样的关键规律。

### 5. 序列调整类

这类题要求对数组或字符串做调整，使其满足某种性质，同时让代价最小或结果最优。

典型思路：

- 当发现局部冲突时，优先做对后续影响更小的修改。
- 关注“改哪个更不吃亏”。
- 有时需要先排序，有时需要从左到右直接贪。

典型题目：

- `376. 摆动序列`
- `1005. K 次取反后最大化的数组和`
- `738. 单调递增的数字`

这类题的关键在于：局部调整以后，是否能让后面更容易保持合法或更优。

### 6. 排序后决策类

这类题一般没有特别明显的“直接贪”痕迹，但排序之后规律会变得很清楚。

典型思路：

- 先按一个维度排序，必要时第二个维度反向排序。
- 排序之后再逐个决策。
- 重点是确定“谁先处理，谁后处理”。

典型题目：

- `406. 根据身高重建队列`
- `56. 合并区间`

这类题的核心不是排序本身，而是通过排序把复杂关系转化成可以局部决策的问题。

## 简短思考框架

贪心没有固定模板，但可以先套这个思考框架：

```go
// 1. 是否需要排序
sort(...)

// 2. 定义答案和过程状态
result := ...
state := ...

// 3. 一次遍历
for _, x := range nums {
    // 当前这一步是否应该选它
    // 如果选，为什么是当前最优
    // 选完之后如何更新状态
}

// 4. 返回结果
return result
```

真正需要固定下来的，不是代码模板，而是这几个问题：

- 我这道题贪的到底是什么。
- 为什么当前这样选不会让后面更差。
- 排序依据是什么。
- 遍历过程中维护的状态是什么。

## 刷题注意点

- 贪心题不要只记结论，要记“为什么这样贪”。
- 一旦贪心策略无法自圆其说，就要警惕它可能是错的。
- 很多贪心题的关键不是代码，而是排序规则。
- 不要把“看起来合理”当成“已经证明正确”。
- 如果问题需要综合很多历史状态，往往要考虑动态规划，而不是硬套贪心。

## 小结

贪心算法的本质，不是套某个固定模板，而是：

- 先找到局部最优策略
- 再证明局部最优能够推出全局最优

所以做贪心题时，可以始终围绕下面三件事展开：

1. 这一题的目标是什么。
2. 每一步应该优先贪什么。
3. 为什么这样贪不会吃亏。

把这三件事想清楚，很多贪心题就会从“感觉题”变成“有依据的选择题”。
